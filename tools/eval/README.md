# Evaluation harness (P2.8)

Measures a pinned model on a COCO-format labelled set and writes its model card.

```bash
# 1. Detections with the production engine and letterbox path (ai-worker must be built)
node tools/eval/detect-images.mjs --gt my-site/annotations.json --images my-site/images \
     --model yolox-tiny --out /tmp/dets.json
# 2. Metrics (AP as pycocotools; precision/recall/FP at the operating threshold)
node tools/eval/coco-eval.mjs --gt my-site/annotations.json --dets /tmp/dets.json \
     --score-threshold 0.4 --duration-hours 24 --out /tmp/metrics.json
# 3. Model card (NOT EVALUATED unless --real-site-data and >= 500 labelled instances per class)
node tools/eval/model-card.mjs --model yolox-tiny --metrics /tmp/metrics.json \
     --dataset "Site X, 24 h, 2026-10" --real-site-data
```

- `coco-eval.mjs` has no dependencies; `__tests__/coco-eval.test.mjs` checks mAP, mAP50 and
  per-class AP against pycocotools COCOeval (reference generated by
  `tools/reference/coco_eval_reference.py`).
- FP per hour needs the footage duration the frames were sampled from (`--duration-hours`).
- `sample/annotations.json` is a four-image smoke sample (public-domain/CC0 scikit-image pictures,
  coarse hand annotations, CC0). It tests the harness, not the model; cards built from it say
  NOT EVALUATED.
- `retrieval-eval.mjs` scores crop search (recall@k, hit rate with a 95% Wilson interval, MRR) from
  a labels file and the rankings the search API returned; see `docs/operations/SEMANTIC_SEARCH.md`.
  It refuses missing results, the query crop inside its own ranking and duplicates, and says
  NOT EVALUATED unless `--real-site-data` is given with at least 100 labelled queries.
  `__tests__/retrieval-eval.test.mjs` checks it against hand-computed values.
- Real numbers need labelled frames from real Indian sites (action plan P2.10, HUMAN-REQUIRED):
  at least 500 instances per v1 class, captured with consent and signage (DPDP).

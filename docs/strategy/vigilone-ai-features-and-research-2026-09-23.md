# VigilOne VMS — AI Feature Inventory & External Research, 23 Sept 2026

Repo: github.com/Nopenope69/VMS, HEAD `12c4ed8` (four UI-only commits after the 14 Sept round-2 review; no AI code changed).

## Part 1 — What AI do we actually have?

**Short answer: no real machine-learning inference exists anywhere in the codebase.** No model files (.onnx/.pt/.tflite), no Python, no inference dependency in `backend/package.json`, no GPU/NPU container in `docker-compose.yml`. What exists is (a) one classical computer-vision signal, (b) a set of well-built "AI-ready" plumbing/logic layers that wait for a detector that has not been attached, and (c) a few places where the wording implies more than the code does.

| # | Feature | Files | Real today? | Notes |
|---|---|---|---|---|
| 1 | Scene-change / motion episode detection | `services/motion/sceneChangeDetector.service.ts`, `detectionZone.service.ts`, `routes/camera.routes.ts:198` | **Real (classical CV, not ML)** | Spawns ffmpeg on the MediaMTX substream at 320x180 @ 1 fps with `select=gt(scene,0.4)`; parses `lavfi.scene_score`; IDLE→ACTIVE→COOLDOWN(60 s) state machine; creates Event, starts recording, ingests into IncidentOrchestrator. Inclusion/exclusion polygon masks are real but only applied when coordinates are supplied — ffmpeg scene score has no coordinates, so zones are effectively unused on this path. |
| 2 | Edge AI Runtime supervisor | `services/ai/edgeAiRuntime.service.ts` | **Shell only** | Bounded queue (100) + writes `DetectionEvent` rows + telemetry. Nothing loads or runs a model. `submitDetection()` has no callers outside its own definition. `modelLoadState` is inferred from counters, not from a loaded model. |
| 3 | Indian ANPR aggregation | `services/anpr/plateTrackAggregator.service.ts`, `routes/anpr.routes.ts` | **Post-processing only** | Multi-frame OCR voting, positional O/0/I/1/B/8/S/5/Z/2 correction, 36 state/UT codes + BH series, dedupe, watchlist hit → alarm. | 6 | Video redaction (faces/plates) | `services/privacy/videoRedactor.service.ts`, `privacyPolicy.service.ts`, `routes/privacy.routes.ts` | **Filter generator real; job execution FAKE** | `generateFfmpegFilter()` builds real `drawbox`/`delogo` chains from supplied masks. The default `modelVersion` is the hard-coded label `'1.2.0-yolo-cctv'` although no YOLO model exists. **Not present at all:** person/vehicle/animal detection, object tracking, face detection/recognition, plate detection/OCR, semantic (text→video) search, VLM/LLM summaries or alert verification, audio analytics, fire/smoke, PPE/helmet, people counting, ONVIF Profile M/analytics-event ingestion from camera-side AI, model registry/versioning, model licensing/SBOM for weights, drift or accuracy monitoring.

**Good news:** the plumbing is unusually ready. `DetectionEvent` schema (trackId, normalized bbox, centroid, attributes, snapshot), the license-aware `THIRD_PARTY_LICENSES.md` policy (already bans AGPL like Ultralytics/OpenALPR), the 320x180@1fps substream discipline, chain-of-custody, and the rule DSL are all shaped correctly. The missing piece is one thing: a detector process that emits `DetectionEvent`s.

## Part 2 — Research: what should we copy, buy, avoid

### 2.1 Reference architecture to copy: Frigate (MIT)
- Pipeline = staged filtering: decode low-res substream → cheap motion detection → merge motion boxes into regions → run ML **only on those regions** → track → retention logic. Our scene-change probe is a coarser version of stage 1.
- Enrichments bolted on top of tracked objects: semantic search (Jina CLIP v1 small/large, text→image and image→image, 8 GB RAM min), face recognition (FaceNet "small" on CPU / ArcFace "large" on GPU, multi-frame aggregation, thresholds 0.7/0.9/0.8), LPR (YOLOv9 plate detector + PaddleOCR, dedicated "LPR camera" mode, fuzzy match distance, known-plate list with regex/wildcards, `format` regex validation, enhancement level), bird/custom classification, GenAI descriptions via Ollama/llama.cpp/OpenAI-compatible (roles: descriptions, chat, embeddings), triggers on similarity thresholds.
- Frigate+ business model: users submit real frames from their own cameras → labelled → base model + per-customer fine-tune; models typed per hardware (mobiledet for Coral, YOLO-NAS/YOLOv9 for GPU/Hailo/RKNN).
- Detector plurality: Coral, Hailo-8/8L, OpenVINO (Intel iGPU/NPU), TensorRT (Jetson), RKNN (RK3588 etc.), ONNX, MemryX, AXERA. Only one detector type per instance.
- License MIT; name/logo trademarked. We can read and learn from it freely, but do not ship their branding.

### 2.2 Model licensing — the single biggest legal trap
- Ultralytics YOLOv5/8/11/YOLO26: **AGPL-3.0** (code and weights). Running behind an API triggers network-copyleft. Your own `THIRD_PARTY_LICENSES.md` already forbids this. Also OpenALPR (AGPL).
- Permissive detectors: **RF-DETR Nano→Large (Apache-2.0)** (XL/2XL are under Roboflow's proprietary PML 1.0 — avoid), YOLOX, RT-DETR, D-FINE, DEIM, PP-YOLOE, DAMO-YOLO (Apache-2.0), RTMDet (MIT), YOLO-NAS (code Apache, but pre-trained weights carry special terms — verify), LibreYOLO (MIT reimplementations). RF-DETR Nano latency 2.3 ms on a T4 with TensorRT FP16.
- Face: InsightFace code is MIT but **buffalo_l / antelopev2 model weights need a commercial licence**. Alternatives to evaluate: OpenCV YuNet (detector), FaceNet/ArcFace re-trained on licensed data, or buy the InsightFace licence.
- Vendor model-zoo traps: some NPU vendors won't distribute YOLO artifacts because of AGPL (MediaTek), some zoos are non-commercial (HiSilicon). Compiled `.hef`/`.rknn` artifacts are chip-and-toolchain-version specific.
- Trackers (ByteTrack, OC-SORT, BoT-SORT) are MIT reference code. ByteTrack ≈ 14 ms/frame/stream on CPU (≈35 streams on 16 cores); BoT-SORT-ReID ≈ 33 ms (≈16 streams) but keeps identity through long occlusions. Cross-camera IDs are NOT transferable without a dedicated Re-ID layer.
- Roboflow `supervision` (MIT) already implements zones, line counters, dwell time, heatmaps, speed estimation — a fast way to validate our spatial engine against a known implementation.

### 2.3 ANPR for India specifically
- Building blocks: `fast-alpr` (MIT; YOLOv9-t-384 plate detector via `open-image-models` + `fast-plate-ocr`, ONNX Runtime with CPU/CUDA/OpenVINO/DirectML/QNN); Frigate's YOLOv9 + PaddleOCR (Apache-2.0) pair. Neither ships an Indian-tuned OCR — you must fine-tune.
- Data: "Indian Licence Plate Dataset in the wild" (16,192 images, 21,683 plates, 10 states, quad-point annotation; code at github.com/sanchit2843/Indian_LPR — licence not stated, verify); VisionPlate ANPR (IEEE DataPort, 403 on fetch — not verified); Roboflow Universe and a HuggingFace Indian plates set (licences vary). The paper's baseline is only 75.6% character accuracy with perspective correction, and LPRNet fails on two-line plates — two-wheeler two-line plates and non-standard fonts are the real Indian problem. Your positional-correction and BH/state validation logic is a genuine differentiator on top of OCR.
- Related Indian ITMS use cases with public prior art: helmet / triple-riding / red-light detection with e-challan PDF generation (SmartChallan repo, a Frontiers 2025 paper using NVIDIA TAO + YOLOv8 — the YOLOv8 part is AGPL, swap the detector).

### 2.4 Search and generative AI (where the market is going)
- **Verkada AI-powered search**: free-text queries ("person holding Louis Vuitton bag"), a large public vision-language model + proprietary pre-processing/caching so queries are fast; built-in moderation; example queries by industry. May 2026 updates add inactivity detection, AI deterrence with escalation, natural-language audit-log search and natural-language schedule setup.
- **Milestone** (Hafnia VLM fine-tuned from NVIDIA Cosmos Reason on licensed, anonymised data): AI Search (end-2026, on-prem via BriefCam for air-gapped), XProtect Video Summarization (clip + prompt → structured incident report, hooked into the rules engine), Video Anonymization (brighter AI), VLM motion-verification to cut alarm fatigue ~30%. Reported +4.4% alert-verification accuracy from fine-tuning.
- **NVIDIA Metropolis VSS blueprint** (Apache-2.0 repo, but needs NVIDIA GPUs/Jetson AGX Orin class and NIM models): perception → analytics → agent layer; VLM-verified alerts, visual Q&A, reports, long-video summarisation, MCP tool interface.
- **UniFi AI Key**: separate PoE++ edge appliance that adds NL search, AI alerts, LPR/face, summaries; capped at ~1,000 smart detections/hour with a 200-event queue and up to 15 min lag — a reminder to design explicit queue/priority behaviour.
- **OpenNVR** (AGPL platform, Apache SDK, early stage): the most relevant architectural idea — a published **AI Adapter Contract** (REST/WebSocket) so any model becomes a hot-swappable, fingerprinted (SHA-256) adapter with correlation IDs threading alert → inference → model version. Default-deny egress modes (`offline`, `local_only`).
- Local VLM reality check: 7–11B models at Q4 need ~6–8 GB VRAM and 10–20 tokens/s on an RTX 4070; ~0.5–3 s per frame. Good for *verifying* a small number of already-flagged events, not for continuous 24/7 analysis. A 2025 arXiv evaluation of ≤8B open VLMs on UCF-Crime got only 27–35% top-1 accuracy (82–86% on simple fight/no-fight) and concluded they are "not yet reliable enough for autonomous surveillance". Recommended pattern: cheap edge detector → VLM re-scoring only of borderline events → human. Plan 4–8 weeks of site tuning; target FP ≤ 5 per 1,000 reviewed hours.
- Semantic search building blocks: SigLIP 2 (Apache-2.0) or Jina CLIP embeddings + pgvector in the Postgres you already run; embed one crop/thumbnail per tracked object rather than per frame.

### 2.6 India compliance, corrected
- **BIS CRS (official guideline PDF, crsbis.in)**: mandatory for CCTV **cameras and recorders**, requires IS 13252 (Part 1) + Essential Requirements ER:01 test reports from third-party labs; gazette 9 Apr 2024, deadline 9 Apr 2025. The official document does **not** mention VMS/software or analytics.
- **STQC IoT scheme P01 (official PDF)**: covers **CCTV cameras only** (hardware/firmware/process/development security; SBOM, anti-rollback, signed updates, no hard-coded credentials). It does **not** cover NVR/VMS software or AI.
- Several vendor blogs (ArcisAI, VMukti, others) claim a separate "STQC-certified VMS" is required for government/PSU/GeM — I could not confirm this from an official MeitY/STQC document. Treat as **unverified**; ask STQC / a GeM buyer directly before you build a certification plan around it. The good news either way: your SBOM, anti-rollback, signed-update, tamper-evident-log work maps well onto the checklist STQC uses for cameras.
- **DPDP Act 2023 / Rules (notified 14 Nov 2025)**: facial data is treated as sensitive in practice; the installing organisation is the data fiduciary and the VMS vendor is usually a processor (a fiduciary when it hosts). Individual consent for CCTV is impractical, so signage/notice is the norm; Section 17 exempts security/law-enforcement retention. Penalties up to ₹250 cr; enforcement expected to begin in 2027. Design implications: purpose-limited face features, automated purging of embeddings and snapshots, RBAC + audit on every biometric query, and a per-tenant switch that keeps 1:N face search off by default.
- **India AI Governance Guidelines (Nov 2025)**: no new AI law; existing IT Act + DPDP apply; emphasis on accountability, dataset documentation, explainability, and an AI Safety Institute. Model cards + per-inference provenance are cheap insurance.
- **Section 63 BSA evidence**: you already generate SHA-256 hashes and Part A/B certificates. For AI-derived data, log model name/version, confidence, timestamp, camera in immutable rows (also what the 2026 provenance literature recommends), and record any enhancement/redaction as a derivative that links back to the master hash. C2PA 2.2 added video and live-stream segment signing — worth tracking as a future export format. **The current fake redaction hash breaks precisely this promise.**

### 2.7 Indian competitive landscape
Videonetics (self-described #1 Indian VMS per Omdia for seven years; VMS + VA + TMS + FRS + VSaaS; ONVIF full member; ANPR, face, crowd, behaviour analytics), VMukti (claims STQC-certified VMS, 900+ deployments), Staqu, Wobot, Vehant (ITMS), IndoAI, CP Plus, Sparsh, plus global Hikvision/Dahua. Differentiation space for an edge-first VigilOne: transparent per-inference provenance, court-ready evidence chain, permissive-licence model stack (no AGPL exposure), air-gapped operation, and honest, published precision/recall per analytic ("if there is no benchmark and no way to pilot it on your data, it is a slide, not a feature").

### 2.8 Standards worth adopting
- **ONVIF Profile M**: standard scene-description metadata (normalised bbox, object ID, class: Human/Vehicle/Face/LicensePlate/Bag…, optional plate text) + optional MQTT JSON events. Consuming camera-side analytics is far cheaper than running your own for every stream. Reality: Axis, Bosch, Hanwha, i-PRO support it; Hikvision/Dahua/Reolink/Uniview mostly do not, so plan proprietary adapters (ISAPI/SDK) too. Archive metadata alongside video (most VMSs discard it), normalise class taxonomies, keep NTP drift <100 ms. Your ONVIF client currently does discovery/PTZ only — no event subscription.
- MediaMTX + ffmpeg substream approach is consistent with Frigate's dual-stream design.

## Part 3 — Recommended path (ordered)

0. **Now:** fix `executeRedactionJob` (either run real ffmpeg + hash the real output, or throw "not implemented" and hide the route); remove the fake `'1.2.0-yolo-cctv'` default; add a test that fails if a job completes without an output file.
1. **Design the AI Adapter Contract** (borrow OpenNVR's idea): a separate, sandboxed inference worker (own container, Python/ONNX Runtime or DeepStream) speaking a small versioned protocol (frame/crop in → detections out) and emitting `DetectionEvent`s with `modelId`, `modelSha256`, `modelLicense`. Add a model registry table and put model provenance into the audit chain.
2. **Phase 1 detector (person/vehicle/bike):** RF-DETR Nano/Small or YOLOX (Apache-2.0) exported to ONNX; run on motion regions from substream; ByteTrack for tracks; feed the existing spatial engine and rule DSL. Validate spatial engine numerically against `supervision`. Publish precision/recall on your own footage.
3. **India ANPR:** two-stage plate detector + OCR (fast-alpr / PaddleOCR-style), fine-tuned on Indian data incl. two-line two-wheeler plates; keep your aggregator, watchlist and BH/state validation. Dedicated-LPR-camera mode like Frigate.
4. **Alert verification with a small local VLM** on flagged events only (Qwen-class ≤8B, Ollama/llama.cpp, OpenAI-compatible fallback disabled by default in air-gapped mode) — cuts false alarms and gives operators a readable reason.
5. **Semantic search:** SigLIP/CLIP embeddings of object crops in pgvector; NL query box modelled on Verkada's UX (industry example queries).
6. **Privacy pipeline:** face/plate detector → temporal masks → real ffmpeg redaction, with derivative hash chained to the master evidence (fixes item 6 above).
7. **Compliance:** confirm STQC scope directly; keep face 1:N off by default with DPDP purpose-limitation controls; add ONVIF Profile M ingestion and metadata archiving.
8. **Fine-tuning loop (Frigate+ style):** opt-in per-site frame collection and labelling to build a proprietary Indian-conditions dataset — the actual moat.
9. **Hardware:** target an Intel Core Ultra (NPU+iGPU) reference appliance first (no extra parts, hardware decode), Hailo-8 as the add-in tier, Jetson only if a customer wants DeepStream/VLM density.

# VigilOne Edge NVR: Hardware Compatibility Matrix

**Document reference:** `VIGILONE-HCM-2026-V2`
**Rule:** a device is **Validated** only when a bench report produced by `scripts/bench/bench-camera.mjs`
against the real device is committed under `docs/operations/bench-results/` and appears in the
generated table in section 2. Nothing else in this document is evidence.

> **Correction (2026-09-26).** Version 1 of this document classified four camera models, a switch, a
> server and three drives as "Validated Benchmark Baseline" with firmware versions and stream
> envelopes. No such testing had taken place: VigilOne has not yet run on a real camera. Those rows
> were self-authored and have been reclassified below as candidates for the bench (P1.6, HUMAN-REQUIRED).

---

## 1. Classifications

| Classification | Meaning |
| --- | --- |
| **Validated** | A committed bench report for this exact model and firmware passed every step (section 2). |
| **Bench candidate** | Planned for the first real bench (P1.1/P1.6). Not tested. |
| **Untested** | Expected to work by protocol (ONVIF Profile S/T, RTSP over TCP). Not tested. |
| **Not recommended** | Engineering judgement based on the device class. Not tested either. |

## 7. Capacity

No capacity figure is claimed. Capacity envelopes will be stated from the P1.6 16-camera 72-hour
soak report (`scripts/soak/soak-runner.mjs`) once it exists. Software rehearsals with simulated
cameras are labelled `SIMULATED-CAMERAS` and do not establish capacity.

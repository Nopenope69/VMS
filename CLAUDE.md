## Rules (learned the hard way)
- No fake success: explicit error codes, no hard-coded versions/hashes/metrics (`npm run check:no-fake-success`), mocks only in tests.
- CI runs about 2 Jest workers against one shared real Postgres:
  - tests create their own tenant and clean up
  - fixture names are unique per run
  - real-DB suites use `jest.setTimeout(60000)`
- Timing: file mtimes can be sub-ms ahead of `Date.now()`. Use `isWithinActiveWriteGrace()` from `crashRecovery.service.ts`; don't compare ages directly.
- Shell tests under `pipefail`: use here-strings, not `echo | grep -q` (SIGPIPE false failures).
- Before pushing:
  - `cd backend && npx jest --maxWorkers=2`
  - `npm run check:model-licenses`, `check:no-fake-success`, `check:dependency-licenses`, `check:feature-flag-docs` and `check:hygiene`
  - `cd services/ai-worker && npm run build && npx jest`
  - `cd frontend && npm run build && npm run check:no-demo`
  - `bash scripts/__tests__/installer.test.sh`
- New feature flags default OFF in `backend/src/config/featureFlags.ts`, then run `npm run docs:feature-flags`.
- Licences: MIT/Apache-2.0/BSD/ISC only. Candidate models (e.g. SigLIP 2) go in `candidateModels` in `scripts/models/models.lock.json`. **Only a human writes licence approvals.**
- Git:
  - one PR per phase, branched from `master`, targeting `master` (check the base branch)
  - open PRs only when the owner asks
  - no model identifiers in commits or PRs
- Owner's Mac has no `gh` CLI. Give GitHub-UI steps or exact git commands.
